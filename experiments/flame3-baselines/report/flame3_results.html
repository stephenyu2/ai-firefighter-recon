FLAME 3 Fire Detection Baselines

I tested 26 ways to answer one question about each drone frame: is there fire? They range from a one-line temperature rule to off-the-shelf vision models, vision-language models, and models fine-tuned on FLAME 3 with LoRA. Everything ran on a MacBook (Apple M5 Pro GPU). This page covers the data, the results, how fast each model runs, and whether the method holds up.

Key findings

  • Whole-frame fire vs no fire is close to solved on this subset. The hottest pixel alone gets 0.998 recall with 0 false alarms. Zero-shot CLIP on RGB, with no training on our data, gets 0.987 recall with 0 false alarms.
  • The labels come from temperature. No-fire frames peak at 47 C and fire frames start at 108 C, so thermal models are close to perfect by construction. The informative tests are RGB-only models and the two hard slices: fire frames from the flights that also have no-fire frames, and very small fires.
  • The backbone matters more than the adapter. LoRA lifts a public fire classifier, trained on ground-level photos, from 0.68 to 0.92 recall, but it adds 10 false alarms and still catches only 55% of the mixed-flight fires. DINOv2 with the same LoRA setup reaches 0.990 recall with 0 false alarms, and on thermal it makes no mistakes at all.
  • New flights separate the trained models. Trained only on October 25 and 26 and tested on the six October 27 flights, the RGB linear probes fall to 0.94 to 0.98 recall. DINOv2 with LoRA (0.997) and the fully fine-tuned ResNet-50 (0.992) hold up, and so does zero-shot CLIP (0.995).
  • A random split would have flattered us. Splitting frames at random, ResNet-50 appears to catch 94% of the mixed-flight fires. With time-based folds and a 30-second buffer it catches 77%. Neighboring frames are near-copies, so a random split mostly measures how well a model remembers frames it has already seen.
  • Vision-language models rank frames well but answer badly. Molmo 2 4B answers yes on only 40% of fire frames, yet its yes-probability ranks frames with ROC-AUC 0.993. A threshold set on other frames lifts recall to 0.97 at 0.89 specificity. Use the probability, not the text answer. Molmo 2 8B ranks every frame correctly (ROC-AUC 1.000); calibrated, it reaches 0.98 recall with 1.00 specificity, while its literal answer still misses 39% of fire frames.
  • Dense smoke blinds RGB. In frames engulfed by smoke, the RGB image is a flat gray wall and the RGB models say no fire. The thermal TIFF shows tens of thousands of burning pixels in the same frames. The detector should be thermal-first.
  • Speed. On this laptop, 14 of 18 benchmarked models stay under our 30 seconds per minute of footage budget at 1 frame per second. The fastest is the temperature rule at 0.6 ms per frame.
  • The method needed two fixes, and I reran everything they touched. Adjacent frames 3 seconds apart could land on both sides of a split, so trained models now drop training frames within 30 seconds of any test frame. I also added a full-day holdout. Most trained models moved by a point or two, but Fire ViT + LoRA lost 29 points and ResNet-50 full fine-tune lost 12 points of mixed-flight recall, so they had been leaning on near-duplicate frames.

The data

The open FLAME 3 computer-vision subset is one prescribed burn at Sycan Marsh, Oregon, captured October 25 to 27, 2022 with a DJI Matrice 30T (dates from the photo metadata). It holds 738 image sets: 622 labeled fire and 116 labeled no fire. Each set has a 4000x3000 RGB photo, a 640x512 RGB crop aligned to the thermal camera, a colorized thermal JPG, and a thermal TIFF with a temperature in Celsius for every pixel. Labels are folder names only. There are no masks or boxes.

Things that change how we should use this data

  • File numbers are shuffled relative to capture time. Splitting by file number is a random split, so splits must use the photo timestamps.
  • The thermal JPG is normalized per image and loses absolute temperature. Its overall darkness alone ranks fire vs no fire with ROC-AUC 1.000, which is an artifact, not a signal. Model on the Celsius TIFF instead.
  • Masks should use a cut near 80 C. The paper's 200 C flaming heuristic gives empty masks for every October 25 frame.
  • Our proposal says FLAME 3 is from Arizona. The open subset is Oregon. Arizona is FLAME 2 and three of the burns that are not public.
  • The Kaggle mirror lists an MIT license. IEEE DataPort's terms say CC BY. Either way, cite the paper and the DataPort DOI.

Methodology and best practices

The checklist below covers each practice, whether it was followed, and the evidence. Two gaps turned up in an audit partway through: near-duplicate frames across the split, and flights that appeared on both sides. Both were fixed and every affected model was rerun. The tables on this page use the fixed protocol.

PracticeStatusWhat I did
Held-out test data for every trained modelFollowed5-fold cross-validation. Each frame is predicted once, by a model that never trained on it.
Split by capture time, not by frame or file numberFollowedFile numbers are shuffled, so frames are grouped into 60-second windows from the photo timestamps. No window spans train and test.
Time buffer between train and testAdded after auditBefore the fix, 83 of 738 test frames (11%) had a training frame 3 to 6 seconds away. Trained models now drop training frames within 30 seconds of any test frame. Every trained model was rerun.
Whole flights held outAdded after auditDay holdout: train on October 25 and 26, test on all frames from the six October 27 flights. Measures recall only, since that day has no no-fire frames.
Thresholds chosen away from the test foldFollowedRecall-tuned thresholds come from inner validation frames for trained models and from the training folds for zero-shot models.
No tuning on the test setMostlySettings were fixed before running: probe regularization 0.1, LoRA rank 16, learning rate 3e-4, 8 epochs, one prompt per model. I changed the threshold-picking rule once after seeing results because it sat too close to the training data. That affects only the recall-tuned rows.
Preprocessing fit on training data onlyFollowedFeature scaling is fit inside each fold. Image normalization uses fixed ImageNet statistics.
Class imbalance handledFollowedBalanced class weights in every trained model. Results report recall, precision, specificity, and false alarms instead of accuracy, since always saying fire scores 84% accuracy.
Stratified foldsFollowedEvery test fold has 20 to 30 no-fire frames.
No label leakageVerifiedModels receive only pixels and a fixed prompt. File paths contain Fire and No Fire but never reach a model. Retraining probes on shuffled labels drops test ROC-AUC to chance (table below).
Same frames for every modelFollowedEvery row scores all 738 frames, so numbers compare directly.
Uncertainty reportedPartly16-shot runs use three seeds. Full-data runs use one seed per fold. With 116 no-fire frames, one false alarm moves specificity by about 0.009, so small gaps between top models are noise.
ReproducibleFollowedFixed seeds, pinned package versions, one script per step. Apple GPU kernels are not bit-exact, so reruns can differ slightly.
Hard slices defined in advancePartlyThe mixed-flight slice came from data inspection. The small-fire cut was added after the first zero-shot results. Treat both as diagnostics.
Generalization beyond one burnNot yetOne burn, and every no-fire frame comes from two flights. Boreal's empty frames would test false alarms on new terrain, but Fairdata needs a browser download.
Pretraining overlapUnknownThe off-the-shelf models do not publish their training data, so some may have seen FLAME images.

What this does not show

  • Fire presence per frame only. Masks and spread direction are not evaluated yet.
  • One prescribed burn in good weather. No night flights, no real wildfire, no heavy smoke from other sources.
  • One prompt per vision-language model. A different prompt could change their numbers.
  • Hosted commercial vision models were not run. They need a paid API key.

What this means for each of us

Data (Caroline)

  • Build splits from photo timestamps with a 30-second buffer, not file numbers.
  • Make masks from the Celsius TIFF at about 80 C. Do not feed the thermal JPG to models.
  • Download Boreal's 256 empty frames through the Etsin web page so we can test false alarms on new terrain.

AI ops (Stephen)

  • Use Molmo 2's yes-probability with a calibrated threshold, not its text answer. On this laptop Molmo 2 4B takes about 536 ms per frame.
  • Expect the same calibration problem in spread-direction prompts, and plan to calibrate those too.

Evaluation (Joe)

  • Frame-level recall is saturated. Report the mixed-flight slice, the small-fire slice, a held-out day, and false-alarm counts.
  • Add harder negatives before we claim anything about precision.

Modeling (Spencer)

  • Make the detector thermal-first, with RGB as a backup channel.
  • Move to segmentation on temperature masks, with DINOv2 plus LoRA as the main fine-tune.
  • Always check held-out flights, not just held-out frames.

Reproduce

Code and results live in experiments/flame3-baselines in the team repo, and the README there lists every step. Download the FLAME 3 CV subset from Kaggle, point FLAME3_ROOT at the unzipped folder, then run:

cd experiments/flame3-baselines
pip install -r requirements.txt
export FLAME3_ROOT=/path/to/flame3_cv
python index_dataset.py
python run_baselines.py
python run_zeroshot.py
python run_probes.py purged
python run_probes.py day
./run_finetune_queue2.sh
./run_after.sh
python make_report.py
python report/build_html.py

Python 3.12.13, torch 2.14.1, transformers 5.18.0, peft 0.21.1, timm 1.0.30, scikit-learn 1.9.1, numpy 2.5.3. Molmo 2 runs in a separate environment pinned to transformers 4.57.1 (requirements-molmo.txt).
